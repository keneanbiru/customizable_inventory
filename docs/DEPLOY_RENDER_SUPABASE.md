# Deploy backend to Render + Supabase Postgres

This guide deploys **only the API** (`server`) to [Render](https://render.com) with [Supabase](https://supabase.com) as the database.

## 1. Create Supabase project

1. Go to [supabase.com](https://supabase.com) → **New project**.
2. Choose a region close to your Render region (e.g. US West if Render is Oregon).
3. Save the **database password** (you need it for `DATABASE_URL`).

### Get connection string

1. In Supabase: **Project Settings** → **Database** → **Connection string** → **URI**.
2. Prefer **Session pooler** (port **5432**) for this app and migrations.
3. Replace `[YOUR-PASSWORD]` with your DB password.

Example:

```text
postgresql://postgres.abcdefgh:YOUR_PASSWORD@aws-0-us-west-1.pooler.supabase.com:5432/postgres
```

> Supabase uses database name `postgres` by default — that is fine. You do **not** run `db:create` on Supabase.

## 2. Test locally against Supabase (optional)

In your local `.env`:

```env
DATABASE_URL=postgresql://postgres.xxxx:YOUR_PASSWORD@....pooler.supabase.com:5432/postgres
DATABASE_SSL=true
JWT_SECRET=your-local-test-secret-min-32-chars
```

From repo root:

```bash
npm run db:migrate
npm run db:seed
npm run dev -w server
```

If migrate works, Render will work too.

## 3. Push code to GitHub

Render deploys from Git. Ensure this repo is on GitHub (or GitLab/Bitbucket connected to Render).

## 4. Create Render web service

### Option A — Blueprint (recommended)

1. Render dashboard → **New** → **Blueprint**.
2. Connect this repo.
3. Render reads `render.yaml` at the repo root.
4. After create, set these **manually** in the service **Environment** tab:
   - `DATABASE_URL` — Supabase URI from step 1
   - `FRONTEND_URL` — your frontend URL (for now can be `http://localhost:5173` until client is deployed)

`JWT_SECRET` can be auto-generated by the blueprint; you can replace it with your own.

### Option B — Manual web service

| Setting | Value |
|--------|--------|
| **Root directory** | *(leave empty — repo root)* |
| **Build command** | `NPM_CONFIG_PRODUCTION=false npm install && npm run build -w server` |
| **Start command** | `npm run start:production -w server` |
| **Health check path** | `/api/v1/health` |

**Environment variables:**

| Key | Value |
|-----|--------|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | Supabase connection URI |
| `DATABASE_SSL` | `true` |
| `JWT_SECRET` | Long random string (32+ chars) |
| `FRONTEND_URL` | Your client origin (CORS + OAuth redirects) |
| `TRUST_PROXY` | `1` |

Render sets `PORT` automatically — do not hardcode it.

## 5. First deploy

On each deploy, `start:production`:

1. Runs SQL migrations (`001` … `008`) against Supabase.
2. Starts the Express API.

**Seed admin once** (after first successful deploy):

1. Render → your service → **Shell** (or run locally with production `DATABASE_URL`):

```bash
npm run db:seed -w server
```

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` in Render env before seeding, or use defaults only for testing.

## 6. Verify

- Health: `https://YOUR-SERVICE.onrender.com/api/v1/health`
- Login: `POST https://YOUR-SERVICE.onrender.com/api/v1/auth/login`

## 7. Frontend (later)

When you deploy the React app, rebuild with:

```env
VITE_API_URL=https://YOUR-SERVICE.onrender.com
```

Point `FRONTEND_URL` on Render to that client URL for CORS and cookies.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Build fails: `Could not find a declaration file` / `@types/node` | Set build command to `NPM_CONFIG_PRODUCTION=false npm install && npm run build -w server` (see `render.yaml`) |
| `SSL connection required` | Set `DATABASE_SSL=true` |
| `password authentication failed` | Reset DB password in Supabase; update `DATABASE_URL` |
| Migrations fail on extension | Supabase includes `pgcrypto` / `gen_random_uuid()` — should work |
| Free Render sleeps | First request after idle may be slow (~30s) |
| Cookies / login from another domain | Set `FRONTEND_URL` to exact client origin; configure client `VITE_API_URL` |

## Security checklist

- [ ] Strong `JWT_SECRET` in Render (not the dev default)
- [ ] Strong `ADMIN_PASSWORD` before seed
- [ ] Do not commit `.env` or Supabase password to Git
- [ ] Set `PUBLIC_REGISTRATION=false` unless you want open sign-up
